= Showroom Content Template

A minimal template for creating lab and demo content on the https://demo.redhat.com[Red Hat Demo Platform], built with https://antora.org[Antora].

== Quick Start

. https://github.com/rhpds/showroom_template_nookbag/generate[Create a repo from this template] (suggested naming: `<lab-name>-showroom`)
. Clone your new repo
. Update `content/antora.yml` -- set the title and default attributes for your lab
. Configure `ui-config.yml` -- uncomment the tabs you need (terminal, OCP console, etc.)
. Preview locally:
+
[source,sh]
----
podman-compose up
----
+
Open http://localhost:8080 -- the site rebuilds automatically when you save any content file (powered by https://github.com/rhpds/showroom-images/tree/main/antora[`quay.io/rhpds/antora:v1.3.0`] with file watching).
. Replace the sample pages in `content/modules/ROOT/pages/` with your lab content

== Local Preview

=== File permissions (rootless Podman)

The Antora container runs as UID 1001 and modifies `site.yml` at startup.
With rootless Podman your host files map to UID 0 inside the container, so you must fix permissions before the first run:

[source,bash]
----
podman unshare chown -R 1001:0 site.yml
podman-compose up
----

After stopping the container, reclaim ownership:

[source,bash]
----
podman unshare chown -R 0:0 site.yml
----

TIP: `git checkout -- site.yml` also restores both content and ownership.

== Examples

The `examples/` directory has ready-to-use templates and reference implementations:

* *Demo* (`examples/demo/`) -- Know/Show structure for presenter-led demonstrations
* *Workshop* (`examples/workshop/`) -- Numbered exercises for hands-on participant labs
* *E2E OCP Dedicated* (`examples/e2e-ocp-dedicated/`) -- End-to-end example targeting a dedicated OCP cluster, with solve/validate runtime automation
* *E2E OCP Tenant* (`examples/e2e-ocp-tenant/`) -- End-to-end example targeting an OCP tenant (shared cluster), with solve/validate runtime automation
* *E2E VM RHEL* (`examples/e2e-vm-rhel/`) -- End-to-end example targeting a RHEL VM, with solve/validate runtime automation

Demo and Workshop each contain `templates/` (with placeholders) and `example/` (filled-in samples).
The E2E examples include `runtime-automation/` directories with Ansible solve/validate playbooks per module.

== Key Files

[cols="1,3"]
|===
|File |Purpose

|`content/antora.yml`
|Component config: title, navigation, AsciiDoc attributes

|`content/modules/ROOT/nav.adoc`
|Sidebar navigation (list your pages here)

|`content/modules/ROOT/pages/`
|Your lab content (one `.adoc` file per page)

|`ui-config.yml`
|Showroom tab layout (terminals, consoles, external URLs)

|`site.yml`
|Antora playbook -- do not modify
|===
